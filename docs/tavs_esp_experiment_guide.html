2. System Architecture

TAVS-ESP protects federated learning from Byzantine (malicious) clients. In standard FL, a central server averages gradient updates from many clients — a single poisoned update can corrupt the global model. TAVS-ESP adds three coordinated layers that decide who to trust, how to inspect their updates, and how to safely combine them.

3. Algorithm Walk-Through

Think of TAVS-ESP as a trust-based bouncer system for federated learning. New clients start with low trust and get fully inspected. As they prove honest over many rounds, they earn the right to contribute with less inspection — but the system randomly spot-checks even trusted clients to prevent long-game attacks.

Algorithm 1: Trust-Adaptive Verification Scheduling (TAVS)

The problem it solves: In standard FL, you either verify every client every round (expensive) or trust everyone (insecure). TAVS finds a middle ground: spend verification resources where they matter most.

Trust Score Update (EMA)

Every client i has a trust score T_i(r) that evolves over rounds. When the client is verified (actually inspected), the trust updates using an Exponential Moving Average:

T_i(r) = α · T_i(r-1) + (1 - α) · φ_i(r)

α = 0.9 (how much history matters)
φ_i(r) = behavior score from detection (0.0 = caught attacking, 1.0 = clean)

Intuition: This is a weighted average between the old trust (90% weight) and the new observation (10% weight). It's like a teacher's running impression of a student — one bad test doesn't destroy a good record, but consistent bad scores eventually drag it down.

Example: Client starts at T=0.5. Gets φ=1.0 (clean):

T_new = 0.9 × 0.5 + 0.1 × 1.0 = 0.45 + 0.10 = 0.55

Trust inches up. After many clean rounds, it converges toward ~0.95. One bad round (φ=0.1):

T_new = 0.9 × 0.95 + 0.1 × 0.1 = 0.855 + 0.01 = 0.865

Trust drops, but not catastrophically. Consistent bad behavior eventually pushes trust below 0.15.

When a client is promoted (trusted enough to skip verification), they get pure decay instead:

T_i(r) = α · T_i(r-1) (no behavior observation available)

This means promoted clients slowly lose trust unless they get verified again. It prevents a client from gaming the system by behaving well early, getting promoted, then attacking silently.

Mechanism 3: Trust Ramp (Rate-Limiting New Clients)

A brand-new client could fake good behavior for a few rounds. The ramp prevents trust from growing too fast:

T_i^max(r) = 1 - exp(-(r - r_0) / τ_ramp)
T_i^effective(r) = min(T_i^raw(r), T_i^max(r))

r_0 = round when client joined
τ_ramp = 30 (how many rounds until the cap lifts)

Intuition: Even if a new client has perfect behavior scores, their effective trust is capped by this exponential curve. At round 1 after joining, the cap is 0.0. At round 10, it's ~0.26. At round 30, it's ~0.63. At round 100, it's ~0.96. This forces clients to prove themselves over time, not just in a burst.

Three-Tier Classification

Using effective trust, clients are sorted into three groups every round:

TierConditionAction
Tier 1 (Verified)T_eff < θ_low (0.3)Fully inspected via BVD detection
Tier 2 (Tentative)θ_low ≤ T_eff < θ_highTentatively promoted, subject to budget
Tier 3 (Trusted)T_eff ≥ θ_high (0.8) AND k_trust consecutive clean roundsPromoted, but randomly spot-checked with probability p_decoy=0.15

CSPRNG Decoy Verification

Even Tier 3 clients aren't safe from inspection. Each round, the system rolls a cryptographic dice:

roll = SHA-256(master_key || client_id || round_num)[:8] / 0xFFFFFFFF

If roll < p_decoy (0.15): client is secretly pulled back for verification

Because the roll depends on a secret master key, the client cannot predict when they'll be checked. This defeats "sleeper agent" attacks where a malicious client behaves well until it knows it won't be inspected.

Mechanism 1: Budget Constraint

The system guarantees that unverified clients can never dominate the aggregate. Define the unverified influence ratio:

γ(r) = Σ p_i(r) / Z(r) ≤ γ_budget (0.35)

Z(r) = |V| + Σ p_i (normalization factor)
p_i = σ(c_λ · (T_i - 0.5)) (Bayesian posterior weight, see below)

If too many clients are promoted, the lowest-trust ones get demoted back to verification until the budget constraint is satisfied. This is a hard guarantee, not a soft guideline.

Bayesian Posterior Weight

Promoted clients contribute with a weight proportional to their trustworthiness, using a sigmoid function:

p_i(r) = σ(c_λ · (T_i(r) - 0.5)) = 1 / (1 + exp(-c_λ · (T_i - 0.5)))

c_λ = 8.0 (steepness: higher = sharper transition at T=0.5)

At T_i = 0.5: p_i = 0.5 (half weight). At T_i = 0.1: p_i ≈ 0.018 (nearly zero). At T_i = 0.9: p_i ≈ 0.982 (nearly full weight). This sigmoid curve smoothly maps trust to influence, heavily penalizing untrusted clients.

Algorithm 2: Ephemeral Structured Projection (ESP)

The problem it solves: A sophisticated attacker could craft a gradient that poisons the model but looks normal when inspected. ESP projects gradients into a random subspace that changes every round, making it mathematically impossible to hide poison in the null space of the projection.

Johnson-Lindenstrauss (JL) Lemma

The core mathematical insight: a random linear projection preserves distances between vectors with high probability. If two gradients are far apart in the original 150,000-dimensional space, they'll still be far apart after projection to 500 dimensions.

y_i^(m) = R_m · g_i^(m)

R_m ∈ ℝ^(k_m × d_m), R_ij ~ N(0, 1/k_m)

Property: E[||R · x||²] = ||x||²

Plain English: Generate a random matrix R where each entry is drawn from a normal distribution with mean 0 and standard deviation 1/√k. Multiply the gradient by this matrix. The result is a much smaller vector that statistically preserves the "shape" of the original — outliers in the original space remain outliers in the projected space.

Block-wise Allocation

The model is split into semantic blocks (e.g., attention layers, FFN layers). Each block gets a proportional share of the projection budget:

k_m = floor(k · d_m / Σ d_j)

Example: model has 50,000 params total, k=500
attention_1 (10,000 params): k_m = 500 × 10000/50000 = 100
attention_2 (15,000 params): k_m = 150
ffn_1 (25,000 params): k_m = 250

Ephemeral Seeds (Why It Changes Every Round)

Each round, each block gets a fresh random seed derived from a secret master key:

seed_m(r) = SHA-256(master_key || round_num || block_name)[:8]

This seed generates the random matrix R_m. Since the seed changes every round, the projection matrix changes too. An attacker who reverse-engineers the null space of round r's projection will find their attack exposed in round r+1 because the null space has shifted unpredictably.

Key invariant: Same seed → same matrix (deterministic within a round for all clients), different seed → different matrix (ephemeral across rounds).

Algorithm 3: Block Variance Detection (BVD) + Bayesian Aggregation

The problem it solves: After projection, we need to identify which clients are outliers (Byzantine) and which are honest but happen to have non-IID data (legitimate variance). A naive approach would flag honest non-IID clients as attackers.

Step 1: Robust Aggregate (Coordinate-wise Median)

Instead of computing the mean (which is easily corrupted), compute the median of all projected updates per block:

ḡ_r^(m) = median({y_i^(m)}) for each coordinate

The median is robust: up to ~50% of the values can be corrupted without affecting it.

Step 2: Block-Normalized Z-Scores

For each client, compute how far their projected update is from the median, normalized by the historical variance:

Z_i^(m) = ||y_i^(m) - ḡ_r^(m)||² / (σ̂_m² + ε_stab)

σ̂_m² = running EMA of inlier distances (updated ONLY using clean clients)
ε_stab = 1e-5 (prevents division by zero)

Classification rule: If max_m(Z_i^(m)) > τ_z (threshold, typically 10.0), client i is an outlier. Otherwise, inlier.

Why block-wise? A "sleeper agent" might inject poison into only one layer (e.g., the attention layer) while keeping all other layers normal. A global norm check would average out the localized spike. By checking each block separately, a spike in even one block triggers detection.

Step 3: Variance EMA Update (Inliers Only)

Critical security property: the variance estimate is updated using only inlier data:

σ̂_m²(r) = α_σ · σ̂_m²(r-1) + (1 - α_σ) · mean({dist_i^(m) : i ∈ inliers})

If attackers' distances were included, they'd inflate the variance, making future attacks harder to detect (a "variance poisoning" attack). By excluding outliers, the threshold stays tight around honest behavior.

Step 4: Behavior Scores

Each verified client gets a continuous behavior score for trust updates:

φ_i(r) = max(0, 1 - Z_i^max / Z_max_overall)

Clean clients get scores near 1.0; outliers get scores near 0.0. These flow back to Algorithm 1 for trust updates.

Step 5: Unified Bayesian Aggregation

Finally, combine all clean contributions:

Δw(r) = [Σ_{i ∈ L} v_i · g_i + Σ_{i ∈ P} p_i · g_i] / Z(r)

v_i = 1.0 for verified inliers (full weight)
p_i = sigmoid(c_λ · (T_i - 0.5)) for promoted clients (trust-weighted)
Z(r) = Σ v_i + Σ p_i (normalization)

Verified inliers contribute at full weight. Promoted clients contribute proportional to their trust. Outliers are excluded entirely. This is the "Bayesian" part: the system doesn't just filter bad clients, it weights contributions by confidence.
